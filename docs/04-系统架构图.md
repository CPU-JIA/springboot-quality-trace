# 系统架构图 —— 产品质量追踪系统

本文档用 Mermaid 图补充说明系统整体结构、核心业务闭环和追溯数据链路，可直接用于课程报告或答辩材料。

## 1. 整体系统架构

```mermaid
flowchart LR
    user[用户 / 浏览器]

    subgraph frontend[前端 Vue3 应用（5174）]
        login[登录页]
        layout[主布局 / 角色菜单]
        pages[业务页面]
        charts[ECharts 图表]
        store[Pinia 状态]
        api[Axios API 封装]
    end

    subgraph backend[后端 Spring Boot（8081）]
        interceptor[JWT 拦截器 / 角色校验]
        controller[Controller 接口层]
        service[Service 业务事务层]
        mapper[Mapper / MyBatis-Plus]
        sql[手写 SQL：递归 CTE / 统计]
        common[统一响应 / 异常处理 / 状态机]
    end

    subgraph database[MySQL quality_trace]
        tables[20 张业务表]
        serial[serial_number 单号流水表]
        views[统计与台账视图]
        trigger[触发器]
        proc[追溯存储过程]
    end

    subgraph support[交付与运维辅助]
        swagger[Swagger / OpenAPI]
        druid[Druid SQL 监控]
        scripts[验证脚本 / 截图脚本]
        docs[课程文档 / 答辩清单]
    end

    user --> login
    user --> layout
    layout --> pages
    pages --> charts
    pages --> store
    pages --> api

    api -->|/api| interceptor
    interceptor --> controller
    controller --> service
    service --> common
    service --> mapper
    mapper --> tables
    mapper --> serial
    sql --> views
    mapper --> sql
    trigger --> tables
    proc --> tables

    swagger --> controller
    druid --> database
    scripts --> frontend
    scripts --> backend
    docs --> support
```

说明：

- 前端通过 Vite 开发服务器运行在 `5174`，`/api` 请求代理到后端 `8081`。
- 后端以 Controller、Service、Mapper 分层组织，关键写操作在 Service 层使用事务。
- MyBatis-Plus 承担通用 CRUD，追溯和统计使用手写 SQL。
- MySQL 负责外键、唯一约束、触发器、视图、存储过程和单号流水。
- Swagger、Druid 和脚本用于接口说明、SQL 监控和可重复验收。

## 2. 核心业务闭环

```mermaid
flowchart TD
    master[主数据维护<br/>物料 / 供应商 / 客户 / BOM / 工艺路线 / 检验标准]
    inbound[原材料入库<br/>生成采购批次]
    iqc[IQC 来料检验<br/>合格 / 不合格 / 让步]
    order[生产工单<br/>按产品和计划数量创建]
    issue[生产领料<br/>扣减批次余量并写消耗关系]
    process[工序执行<br/>开工 / 完工 / 顺序门禁]
    ipqc[IPQC 过程检验<br/>控制关键工序放行]
    complete[完工入库<br/>生成半成品或成品批次]
    fqc[FQC 完工检验<br/>控制成品放行]
    shipment[成品出货<br/>记录客户流向]
    trace[双向追溯<br/>查来源 / 查去向]
    defect[缺陷管理<br/>登记 / 处置 / 状态联动]
    recall[召回管理<br/>生成影响面 / 跟踪回收]
    stats[统计报表<br/>合格率 / Pareto / 供应商质量]

    master --> inbound
    inbound --> iqc
    iqc -->|合格或让步| order
    iqc -->|不合格| defect
    order --> issue
    issue --> process
    process --> ipqc
    ipqc -->|通过| process
    ipqc -->|不通过| defect
    process --> complete
    complete --> fqc
    fqc -->|合格或让步| shipment
    fqc -->|不合格| defect
    shipment --> trace
    defect --> trace
    trace --> recall
    recall --> stats
    iqc --> stats
    ipqc --> stats
    fqc --> stats
    defect --> stats
    shipment --> stats
```

说明：

- 追溯链在入库、领料、工序、完工入库、出货过程中自动形成。
- IQC、IPQC、FQC 分别对应来料、过程、完工三个质量控制节点。
- 缺陷处置会联动批次或工序状态，避免问题批次继续流转。
- 召回模块复用正向追溯结果生成影响面，并跟踪已出货和在库受影响批次。

## 3. 追溯数据链路

```mermaid
flowchart LR
    supplier[(supplier<br/>供应商)]
    material[(material<br/>物料)]
    rawBatch[(batch<br/>原材料批次)]
    order[(production_order<br/>生产工单)]
    consumption[(batch_consumption<br/>批次消耗)]
    process[(process_record<br/>工序执行记录)]
    outputBatch[(batch<br/>半成品 / 成品批次)]
    inspection[(inspection_task<br/>检验任务)]
    record[(inspection_record<br/>检验明细)]
    defect[(defect_record<br/>缺陷记录)]
    shipment[(shipment<br/>出货记录)]
    customer[(customer<br/>客户)]
    recall[(recall_order<br/>召回单)]
    recallDetail[(recall_detail<br/>召回明细)]

    supplier -->|供应| rawBatch
    material -->|定义物料| rawBatch
    material -->|生产目标| order

    rawBatch -->|被消耗批次| consumption
    order -->|领料形成消耗边| consumption
    order -->|产出| outputBatch
    order -->|包含| process

    outputBatch -->|出货| shipment
    shipment -->|流向| customer

    rawBatch -->|IQC| inspection
    process -->|IPQC| inspection
    outputBatch -->|FQC| inspection
    inspection -->|检验项目结果| record
    inspection -->|异常生成| defect
    rawBatch -->|批次缺陷| defect
    outputBatch -->|批次缺陷| defect
    process -->|过程缺陷| defect

    rawBatch -->|问题源头| recall
    recall -->|包含| recallDetail
    outputBatch -->|受影响批次| recallDetail
    shipment -->|已出货明细定位客户| recallDetail
```

### 3.1 反向追溯

```mermaid
flowchart RL
    fp[成品批次 batch]
    mo[production_order]
    bc[batch_consumption]
    sf[半成品批次 batch]
    raw[原材料批次 batch]
    sup[supplier]

    fp -->|production_order_id| mo
    mo -->|production_order_id| bc
    bc -->|consumed_batch_id| sf
    sf -->|继续递归| mo
    bc -->|consumed_batch_id| raw
    raw -->|supplier_id| sup
```

用途：从成品批次反查使用过的半成品、原材料和供应商，用于质量问题定位。

### 3.2 正向追溯

```mermaid
flowchart LR
    raw[问题原材料批次 batch]
    bc[batch_consumption]
    mo[production_order]
    fp[受影响成品批次 batch]
    ship[shipment]
    cust[customer]
    recall[recall_order]
    detail[recall_detail]

    raw -->|consumed_batch_id| bc
    bc -->|production_order_id| mo
    mo -->|production_order_id| fp
    fp -->|batch_id| ship
    ship -->|customer_id| cust
    raw -->|发起召回| recall
    recall --> detail
    fp --> detail
    ship --> detail
```

用途：从问题原料批次查找全部受影响产出批次和客户流向，用于召回影响面生成。

## 5. 可放入报告的简短说明

系统采用前后端分离架构。前端基于 Vue3、Element Plus 和 ECharts 构建业务界面，后端基于 Spring Boot、MyBatis-Plus 和 MySQL 实现接口、事务和数据持久化。追溯链以批次为核心，`batch_consumption` 表记录生产领料形成的物料消耗边，`production_order` 表连接投入批次与产出批次，`shipment` 表记录成品客户流向，`recall_order` 与 `recall_detail` 表记录召回影响面和回收状态。系统通过递归 CTE 支持批次双向追溯，通过外键、唯一约束、状态机、触发器和事务保证质量数据的一致性与可追责性。
