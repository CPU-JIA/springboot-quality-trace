## 2. 视图

| 视图 | 用途 |
| --- | --- |
| `v_batch_overview` | 批次台账全景查询，聚合物料、供应商、生产工单和登记人 |
| `v_supplier_quality` | 供应商质量排名，统计供货批次、IQC 合格率、缺陷数和召回数 |
| `v_defect_pareto` | 缺陷 Pareto，按缺陷类型统计频次、数量、占比和累计占比 |

## 3. 触发器

| 触发器 | 触发表 | 时机 | 作用 |
| --- | --- | --- | --- |
| `trg_freeze_batch_on_unqualified` | `inspection_task` | `AFTER UPDATE` | 检验结论变为不合格时，自动冻结待检/检验中/合格在库批次 |
| `trg_freeze_batch_on_unqualified_ins` | `inspection_task` | `AFTER INSERT` | 直接插入终态不合格检验单时，同样触发批次冻结 |

## 4. 存储过程

| 存储过程 | 入参 | 用途 |
| --- | --- | --- |
| `sp_trace_upstream` | `p_batch_id` | 反向追溯：成品/半成品批次向上查原料、供应商、工单、工序和检验摘要 |
| `sp_trace_downstream` | `p_batch_id` | 正向追溯：原料批次向下查受影响产出批次、出货记录和客户 |

## 6. 答辩强调点

- 批次追溯不是字符串拼接，核心由 `batch_consumption` 与 `batch.production_order_id` 两跳递归实现。
- IQC/FQC 和 IPQC 的对象不同，`inspection_task` 用双可空外键 + `CHECK` 保留参照完整性。
- 不合格冻结由应用层状态机处理，数据库触发器作为兜底安全网。
- 供应商质量不只看 IQC 合格率，还统计缺陷和召回归因。
- 单号流水使用唯一键和行锁原子递增，避免并发撞号。
